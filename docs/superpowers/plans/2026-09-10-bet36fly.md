# BET36FLY implementation plan

**Goal:** Deliver the real connectome sports experiment described in the design spec.
**Architecture:** CPU whole-network leaky integrate-and-fire simulator, plastic anatomical mushroom-body connections and a trained spike readout; timestamped data ingestion; FastAPI service and React spectator UI.
**Tech stack:** Python 3.12, NumPy/SciPy/PyArrow/PyTorch, FastAPI, React/Vite/TypeScript.
**Spec:** `docs/superpowers/specs/2026-09-10-bet36fly-design.md`

## Global constraints

- Phase 1 fetches games and emits paper picks. bet365 API/account integration is deferred by the user.
- Preserve full retained anatomical support; name all modeling assumptions and artificial interfaces.
- No fabricated live games, neural traces, learned weights, quotes, test outcomes or profit.
- Use chronological evaluation and pregame-only features.
- No credentials in source, logs, browser responses, or reports.
- Work in this empty user-provided repository; retain data artifacts locally outside git.

## Work sequence

- [x] 1. Import source data and implement/test graph indexing, transmitter signs, sparse dynamics, artificial sensory encoding and plastic anatomical layer. Files: `bet36fly/connectome.py`, `bet36fly/brain.py`, `scripts/prepare_connectome.py`, `tests/test_brain.py`. Preserve edge/contact accounting, deterministic states and anatomical support. Test tiny known graphs before the full data run.
- [x] 2. Implement/test timestamped EPL/MLB ingestion, normalizers and chronological pregame feature extraction. Files: `bet36fly/sports.py`, `bet36fly/features.py`, `scripts/fetch_sports.py`, `tests/test_sports.py`. Never use a game's final result as that game's feature; defer batch updates until all simultaneous observations are encoded.
- [x] 3. Train the neural model on real historical outcomes. Files: `bet36fly/learning.py`, `bet36fly/experiment.py`, `tests/test_learning.py`, `tests/test_experiment.py`. Save checkpoint and progress atomically, validation-select epochs, hold test outcomes out, evaluate controls and checkpoint roundtrip.
- [x] 4. Implement the FastAPI service and paper-pick ledger. Files: `bet36fly/server.py`, `bet36fly/ledger.py`, `tests/test_api.py`. API contract in `docs/api-contract.md`. Expose status, games, prediction activity, training report, ledger, export and source refresh; serialize model access and distinguish failed/stale sources.
- [x] 5. Implement the complete frontend using the generated concept. Files owned by frontend implementer: `web/`. Actual data only; fetch from the defined API, expose loading/empty/error states. Run build and browser interactions.
- [x] 6. Run integration, scientific checks, browser acceptance and a bounded independent code review. Fix confirmed defects with category coverage. Save `output/acceptance.md` and document startup/training/source contracts in README and model card.

## Execution decisions

The user explicitly asked for autonomous work. Design choices are delegated, so no additional design approval pause is needed. The repository is empty and has no prior work to isolate. One frontend subagent may work on the independent UI contract alongside the root's data/model implementation, as requested by the subagent-development skill; no recursive delegation. Review is bounded to concrete defects and one final pass.
