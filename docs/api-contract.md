# BET36FLY sensory application contract

The product is a read-only research application for the completed 2023 MLB sensory confirmation. It never reads historical v1 predictions, ledgers, readiness flags or training progress. No page load or GET calls a neural simulator, fits parameters, fetches sports data or changes the model pointer. The Circuit page reads prepared connectome geometry, which is released anatomy on disk and not a simulator run.

## Pages and navigation

`/#learning` shows the dopamine-learning stage as four separate answers (mechanism implemented; conditioning qualified; plasticity improves held-out prediction; application uses a learned checkpoint) with the measured links, conditioning runs, season backtests, jobs and checkpoint probes. `/#overview` shows the full confirmation, weekly-bootstrap uncertainty and six same-game comparisons. `/#backtest` provides team/date filters and pagination through every confirmation game. `/#backtest/<encoded game_id>` shows a specific matchup. `/#methods` explains the pipeline, chronological splits, limitations, provenance and downloads. `/#circuit` draws the MaleCNS v1.0 anatomy: a sampled soma projection with a strong-edge overlay, anatomy layer filters carrying released counts, a neuron search and inspector, and the display-only caveats. The camera is pointer-driven (drag to rotate, wheel to zoom about the pointer, shift-drag to pan, double-click empty canvas to reset) with slider, button and keyboard equivalents; clicking a neuron inspects it, and a drag that ends over a neuron does not. Unknown and obsolete hashes and path bookmarks resolve to `/#overview`; no version archive is exposed.

The application requests `/api/sensory/summary` once when a sensory page is shown; `/#learning` and `/#circuit` carry their own evidence and never request it. The explorer requests a result page after filter/page changes; details request the selected game. Manual retry is available. There are no polling intervals or mutation controls on the sensory pages. The separate `/#circuit` page requests `/api/brain` once on mount, offers manual retry and never polls. The separate `/#learning` page (below) polls `/api/associative/jobs` every 5 s only while a training job is running and carries explicit job-start, cancel and checkpoint-probe controls whose errors are rendered verbatim. Legacy React components remain unmounted source history and are excluded from the built dependency graph.

## Validated artifact reader

`bet36fly/sensory_evidence.py` binds the data to `configs/sensory-application-lock.json`, a new presentation identity around unchanged frozen artifacts. The confirmation remains `sensory-confirmation-4887cb8c17f6281d8166`. Every read rehashes all small presentation inputs, even when parsed results are cached. Missing, unreadable or symlinked inputs and hash mismatches invalidate delivery. A historical frozen result does not expire merely because time passes; stale or mixed artifact identities fail validation.

The reader checks manifest/evaluation/candidate agreement, complete unique CSV IDs, numeric domains, quality intervals/contact keys, all four response differences, every frozen readout probability and every aggregate metric. No training code or engine is imported. Original independent bootstrap and source/code audits remain recorded historical evidence; this API does not repeat the experiment or claim to revalidate every large upstream source file on each request.

## GET /api/sensory/summary

Returns `status: available`, `identity`, `correct`, `candidate`, all `teams`, `evaluation`, `splits`, `source`, `output_cells` and `downloads`. Evaluation carries full-precision recorded metrics, paired loss intervals, accuracy interval, weeks, replicates, dates and exclusions. Paired loss is **pipeline minus comparator**; the UI explicitly negates both endpoints and reverses their order when displaying improvement. Uniform/silenced probability ties pick home, so their accuracy is not random guessing's 50% expectation.

Unavailable or invalid installations return HTTP 200 with `status: unavailable|invalid`, `identity` and `message`, without metrics. The UI hides any previous success on failure; retry must validate again. HTTP/network errors likewise hide the old result.

## GET /api/sensory/games

Query fields: optional exact `team`, ISO dates `start` and `end` (inclusive UTC), `offset >= 0`, `limit` from 1 through 100 (default 50). Invalid dates/ranges/pages return 422. Results sort by UTC start and fixture ID. Response: `identity,total,offset,limit,summary,games`. Summary covers the entire filtered subset, not just the visible page, and contains `n,correct,accuracy,log_loss,brier`. Empty subsets have `n:0,correct:0` and null metrics. The original full-confirmation interval is never assigned to a filtered subset.

Every game includes its original `game_id,start_time,home,away,home_win`, six saved home probabilities, saved qualities/bounds/contact keys, four neural differences and derived `correct`. The UI presents outcome and pick correctness separately. The full source CSV remains downloadable. Invalid evidence produces 503; no old-model fallback exists.

## GET /api/sensory/games/{game_id}

Returns `identity,game,home,away,output_cells,stimulus_window_ms,duration_ms,bin_ms,evidence_mode,achieved_input_hz,achieved_input_note,trace_note`. Unknown fixture IDs return 404. The home/away probe objects include `team,quality,interval,contact_key,condition,recruited_ids,requested_hz,source_measurement,outputs_hz,seeds,outputs_by_seed`.

Qualities, intervals and keys are persisted in the confirmation CSV. Recruited cells and requested rates are faithfully reconstructed from the frozen recruitment order, source populations and rate anchors. Quality is not a win probability. Both teams use the same mapping, with the fitted home-field term; neither is forced bitter because it ranks second.

The four outputs are Clavicle/ANXXX462a bodies 19480 and 514625, then Quasimodo/GNG042 bodies 15321 and 15734. Saved rates average three seeds over the one-second stimulus (500–1500 ms of a 2000 ms exposure). Individual recorded seed outputs are also shown. The interface uses rate charts, without retaining the old anatomical animation. It never depicts a new neural run per historical game. Per-cell achieved input rates are not delivered by this adapter and remain explicitly unavailable, distinct from generator requests and recorded output rates.

## GET /api/sensory/downloads/{artifact}

The IDs are an explicit allowlist: predictions, evaluation, manifest, integrity, candidate, result, confirmation, cells and responses. Summary returns ready-to-use URLs and SHA-256 values. Unknown IDs return 404; invalid installation returns 503. The endpoint returns exactly the bytes just validated (no second filesystem open), with attachment disposition. It accepts no filesystem paths.

## GET /api/brain (Circuit page, mounted September 14)

Returns the released connectome geometry for `/#circuit`: `dataset`, `nodes`, `edges`, `edge_metadata`, `displayed_neurons`, `total_neurons` and `coordinate_note`. Each node carries a body ID, normalized soma coordinates, its released `type`/`superclass`/`class`/`subclass`/`hemisphere`/`pre`/`post`/`transmitter` annotations, a `classification_source` and a `category` of `alpn|kc|mbon|other|unknown`. A node is `alpn` when its released class annotation is ALPN, `kc` or `mbon` by the corresponding retained population, `other` when the release supplies a type or superclass, and `unknown` when it supplies neither. `edges` are index pairs into `nodes`; each `edge_metadata` entry carries the released `contact_count`, the `modeled_sign` assumed from the presynaptic transmitter annotation, and `plastic`, which means only that the presynaptic neuron is a Kenyon cell and the postsynaptic neuron is an MBON. The page labels that flag "KC→MBON output synapses" and makes no learning claim from it.

**Sampled and display-only.** The payload is not the retained graph. It samples 2,500 neurons that have released soma coordinates, keeping coverage of the ALPN, Kenyon-cell and MBON populations, out of 166,700 retained neurons, and draws only a strong-edge subset among those sampled neurons: at least five anatomical contacts, capped at the 3,500 heaviest, currently 2,133. Coordinates locate somas, so the drawing is a soma projection and not a neuropil or mushroom-body reconstruction. Nothing on the page changes any computation: layer filters, rotation, search and inspection alter the drawing only, and the page requests no prediction, training or checkpoint route.

The response is read-only and available in verification mode. It reads the prepared connectome geometry from `data/brain`: a full read of the node annotation table plus memory-mapped slices of the edge arrays, cached in the runtime for the process lifetime. It builds no simulator, runs no dynamics and loads no checkpoint. A cold read is well under a second; later reads are served from that cache. An absent, empty or partially prepared `data/brain` returns 503 with an explicit message, covered by `tests/test_api.py::test_brain_geometry_reports_an_unprepared_connectome_as_503`; the page then shows that message with a manual retry rather than any stale drawing.

## Startup, verification and compatibility

`make serve` starts the current product with background source-following disabled. The default exported ASGI app creates no legacy Runtime during startup. The historical model pointer is preserved. Existing legacy backend routes remain distinct compatibility APIs, documented in [the historical contract](historical-api-contract.md); they are never consumed or relabeled by the product.

`make serve-verify` starts the guarded read-only factory; `QA_PORT=8766` permits isolated QA when 8765 is occupied. Every response bears `X-BET36FLY-Verification: read-only`; non-read methods are rejected before handlers. Browser preflight checks both that header and the existing `/api/status` verification flag before launching Chromium. The product itself does not request `/api/status`.

`node scripts/verify_sensory_browser.cjs /tmp/bet36fly-sensory-browser` covers navigation, real results, filters, details, exact-byte downloads, loading/empty/unavailable/error recovery, legacy URLs, request isolation and responsive widths. `node scripts/verify_circuit_browser.cjs` covers the Circuit page: routing and hash retention, payload-matched counts, the anatomical layer naming, layer toggles, hover and click inspection, drag-to-rotate, the drag-versus-click distinction, wheel zoom without page scroll, keyboard camera control and reset, explainer pinning, the 11px legibility floor, swatch grounds, 320 px upward overflow, request isolation and the 503 and empty-geometry states, with screenshots at device scale factor 1. Both browser scripts resolve Playwright through `scripts/playwright.cjs`, which honours `PLAYWRIGHT_PATH` because the package is not vendored here. `verify_reward_browser.cjs` and `verify_desk_browser.cjs` are compatibility launchers for the current acceptance suite. Rebuild `web` before browser QA. `make verify` remains the full pytest/Ruff/vitest/build gate.

## Associative learning stage (`/api/associative`, added September 13–14)

The dopamine-learning stage ([contract](EXPERIMENT_ASSOCIATIVE.md), [evidence](evidence/associative-learning-2026-09-13/index.md)) is exposed as a separate page, `/#learning`. It does not change the product's predictions, which remain the frozen sensory confirmation. The four questions (mechanism implemented; controlled acquisition/retention/reversal qualified; plasticity improves held-out prediction; application uses a learned checkpoint) are reported as four separate fields and never collapsed.

- `GET /api/associative/evidence` reads stored manifests only (never imports the engine). Returns `contract {path,sha256,exists}`, `circuit {path,sha256}`, `links[]` (plasticity-off link measurements with `checks` and `odor_code` calibration), `conditioning[]` (one entry per run: `status`, `error`, `entry_gate`, `summary {acquisition_passed,retention_passed,reversal_passed,audit_passed,all_passed}`, `acquisition {criteria, readout, null_arms, null_response_scale, null_gain_scale, arms{...}}`, `retention`, `reversal`, `probes`), `sports[]` (season arms: `arm`, `learning_rate`, `season`, `games`, `status`, `days`, `calls`, `reinforcements`, `final_gains_sha256`, `checkpoints`), `evaluations[]` (`metrics` per method, `paired_loss` as plastic minus comparator, `shuffled_minus_frozen`, `accuracy_interval`, `plasticity_contributes`, `goal_passed`), `stress[]` (continual-learning stress runs: `arm` baseline|recovery, `rho`, `lower_bound_occupancy`/`upper_bound_occupancy`/`above_rest` per compartment at the end, `total_recovery`, `total_bound_contacts`, `memory_by_cycle`, `post_history` acquisition/reversal verdicts, `occupancy` history), `confirmations[]` (one-shot reserved-block confirmations: `season`, `attempt`, `status` `passed_confirmation|failed_confirmation|failed_runtime`, source URL/hash/time, `frozen_candidate_sha256`, per-arm call/reinforcement/gain-hash records, `metrics`, `paired_loss` as plastic minus comparator, `shuffled_minus_frozen`, `baseline_minus_frozen`, `accuracy_interval`, `plasticity_contributes`, `better_than_chance`, `predictions_csv`), `mechanism_qualified` (true only when a conditioning run's stored `summary.all_passed` is true), `qualified_conditioning[]`, `sensory_confirmation_unchanged`. Invalid or missing manifests appear with `valid:false`; nothing is inferred.
- `GET /api/associative/jobs`, `GET /api/associative/jobs/{id}`: explicit job state (`queued|running|completed|failed|cancelled|budget_stopped`), `progress {days,calls,reinforcements,cache_hits,cache_misses,last_day,gains_sha256}`, recent `checkpoints`, `run_identity`, `resumed_from`, `error`.
- `POST /api/associative/jobs` `{protocol, arm, learning_rate?, day_limit?, resume?}` starts one season arm (`plastic|frozen|shuffled`) of a protocol under `configs/`; a second concurrent job returns 409; `resume` names an earlier job of the identical protocol/arm/learning rate and continues deterministically from its last completed UTC-day checkpoint. `POST /api/associative/jobs/{id}/cancel` requests cancellation at the next day boundary. Both return 405 in verification mode.
- `GET /api/associative/checkpoints` lists saved immutable checkpoints (`output/associative/*/checkpoint-*.npz`). `POST /api/associative/predict` `{checkpoint, home, away}` loads that checkpoint into a separate inference engine, probes both team odors with plasticity off and returns `home/away {team, odor_types, response:[MBON05,MBON01]}`, `learned_differences`, `plasticity:false`, `outcomes_consumed:false`, `gains_sha256` and `probability_home:null` (a probability needs a fitted arm readout plus the frozen innate features, which this endpoint does not fabricate). The checkpoint file is never written. 405 in verification mode.
- Every learning job writes under `output/associative/` only. No route reads the pick ledger, the v1 pointer or the legacy registries.
