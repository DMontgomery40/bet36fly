These are explicit frozen trial semantics, not accidental gain resets.

Conditioning ownership includes stage, panel and arm/branch (`bet36fly/conditioning_runner.py:305`). Each arm starts from its own copied unit or acquired-parent checkpoint; canonical gains are updated only by its original training calls (`:329`, `:351`). Probe/replay state is disposable. The timing-unpaired blank starts a new neural trial with no carried cue eligibility, exactly as preregistered. Consequently this control tests separation across those reset trials; it is not a continuously running long-intertrial-interval experiment.

The diagnostic writer calls the engine independently for each frozen, untaught, home-taught and away-taught condition (`scripts/reward_teaching_diagnostic.py:206`, `:262`). Untaught has no injected teaching pulses, plasticity remains enabled, and every single-trial condition starts from unit gains. Its KC/DAN histories can differ from taught histories as learning affects recurrent activity. Only its separate 16-trial cumulative sequence carries gains (`:306`). The conditioning untaught arm has its own checkpoint and the same scheduled cue/blank exposure and seeds. “Independent control” here means a separate circuit execution and state trajectory, not unrelated sensory noise: matched common randomness is intentional. The offline fixed-history shadows cannot substitute for these circuit controls.

## Observable sign and exact comparisons

Responses are actual selected-MBON cue-window spike counts (`bet36fly/conditioning_runner.py:379`), with the same 300 ms window length for acquisition and reversal and each population's own denominator (`:420`). They are not the sports decoder's signed score. `bet36fly/conditioning.py:524` converts retained integer counts to exact rational values for comparisons, and `:586` uses exact float32 checkpoint values and preferred-set sizes. The target/other direction is home A-versus-B and away B-versus-A (`:628`). Both selectivity and actual target response/gain depression must hold (`:652` onward). No population-size normalization, Hz rounding or gain-set-size bias was found in these paths.

The selected KC→MBON plastic support is explicitly required to have positive modeled fast weights (`bet36fly/reward_protocol.py:217`). That supports the direct-synapse depression interpretation but does not guarantee a monotone whole-circuit MBON response under recurrent feedback. The requirement for a real MBON response change is therefore a separate experimental criterion. An output neuron's transmitter sign does not reverse the sign of its own measured firing rate. A learning mechanism that changes some other observable without these named MBON/gain effects does not satisfy this particular preregistration; accepting it would require a reviewed scientific design, not changing a subtraction sign.

## What the qualification gate does and does not establish

`bet36fly/reward_diagnostic.py:298` compares taught-minus-matched-untaught gain sums. Its independent untaught guard uses the mean and sample SD within each eight-cue/channel/seed-set cell (`:307`), without pooling seed sets. It expressly requires `abs(mean) <= 0.5 * SD`. A correctly implemented learning equation can fail that criterion when endogenous KC/DAN activity is correlated or nonstationary. The independent stationary-input reference test is a different experiment; its zero-mean expectation is not evidence that the live circuit's untaught histories are independent stationary processes. This is an acknowledged scientific scope constraint, not a newly found evaluator bug, and the audit does not recommend weakening it.

`bet36fly/conditioning_runner.py:59` requires both members of one independently validated, passing qualification pair before input preparation or engine creation. The current complete archive validator supports `rate-bridge-v1`; `_verify_raw` always leaves replay and sensory invariance unverified (`bet36fly/reward_evidence.py:346`). Current raw archives cannot be promoted by their stored pass flags. The runner/numerical schema accepts only the two implemented rule names (`conditioning_runner.py:1050`, `conditioning.py:902`). A future rule or newly complete raw archive would need an explicit new recording/validator/identity integration before conditioning could accept it. That is an implementation extension boundary already disclosed by the API contract, not permission to reuse a bridge identity or mark old evidence passed.
