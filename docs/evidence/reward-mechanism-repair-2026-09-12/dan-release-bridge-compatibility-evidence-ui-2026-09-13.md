## Newly pinned source boundary

Personally inspected DARELA commit `125c27bc59b0c493c902c8724f58fa3d9d8b354d`, specifically the full `base.py`, `ode.py`, `models.py`, SUR example and README, without importing or executing it. `base.py:116–121` constructs **burst-envelope** S with rounded arguments and both Heaviside endpoints included. `ode.py:11–13` sets `dt=1/f`; `:44–50` updates H first, then uses the product of **new H** in release. `base.py:136–140` uses Euler updates, not exponential event jumps.

By inspection, the example's 50 Hz, start 0.34 s and NP=30 setting includes source grid indices 17 through 47: 31 driving intervals, despite the parameter name. The example explicitly uses short-depression tau 12.5 s. The stimulation loop sums envelopes; overlapping bursts can make S exceed one and reverse the sign of the `(1-S)` recovery coefficient. Encoding every native spike as a source NP=1 burst is therefore not an established per-event mapping. Do not silently reconcile these choices with a different publication parameter row or ideal half-open 30-pulse schedule. Source/math reviewers own that reconciliation. Burst-envelope input, stimulus current, extracellular concentration and electrode output are not automatically calibrated quantities for individual PPL101/PAM12 spikes. These are concrete transfer decisions, not evidence that the current native bridge is wrong.
